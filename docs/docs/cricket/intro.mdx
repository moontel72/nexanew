# 🏏 Cricket System — Overview

The NexaTrace cricket pipeline has **three parts** that work together on
match day:

| Component | Where | Who uses it |
|---|---|---|
| **Cricket Manager Panel** | `https://cricket-manager.traceodd.com` (Flutter app) | Scorer / match manager |
| **Todd Studio** | `https://studio.traceodd.com` (browser) **or** the Windows desktop app | Director / producer |
| **Ground Cameras / Broadcaster** | WHIP apps (OBS, Larix, IRL Pro) or RTSP/RTMP cameras | Camera operators |

## How they connect

```text
Scorer scores a ball in the Manager Panel
        │  REST → Laravel backend
        ▼
Laravel broadcasts `score.updated` on Reverb (WebSocket)
        │  push
        ▼
Rust Media Engine (behind studio.traceodd.com/api)
        │  → scoreboard lower-third, event popups, auto-replay (4/6 = 5s before + 3s after)
        ▼
Todd Studio (director)  +  PGM stream → WHEP viewers / RTMP / SRS HLS
```

- **Ground cameras** publish video to the engine via **WHIP** (or the
  engine pulls **RTSP/RTMP**).
- The **director** switches cameras into the program (PGM) bus in Todd
  Studio.
- The **scorer** drives everything: every ball automatically updates the
  lower-third, fires popups, and triggers slow-motion replays — the
  director only steps in for manual moments (VAR, polls, broadcast
  targets).
